# 共用配色與排版指引

後續A／B／C／D畫面沿用目前「淺灰＋靛紫」配色。共用檔案與分工仍依根目錄agent.md；本文件提供實作參考，不改產品規格。

## 使用既有版型

- 功能頁面以Jinja `{% extends 'base.html' %}` 建立，沿用標頭、登出、主內容寬度、示範環境標記及共用表單樣式。
- `app/static/css/app.css` 是全員共用基礎，由A維護。使用 `var(--accent)`、`var(--muted)`、`var(--border)`，避免每個模組另設主色。
- 主色為 `#6250A5`、背景 `#F5F4FA`、標頭 `#29233F`；卡片採白色。錯誤、警示與成功狀態仍使用紅、琥珀、綠，搭配文字說明。
- B／C／D各自的特殊排版放在模組樣式檔。C目前為 `ordering.css`；B／D不必載入C整份樣式，可參考其卡片、表單與確認視窗。不要為了沿用卡片而覆寫全站 `header`、`button` 或 `label`。

## 排版與操作

- 桌面將相關欄位對齊；長理由放獨立一列，表格或grid子元素設定 `min-width: 0`，顯示長文字時允許換行。
- 手機改為單欄或適合閱讀的少欄配置。數量與其單位保持清楚，勿將大量說明擠在同一行。
- 主要輸入與按鈕至少44px高；次要文字操作也須保留足夠的點擊範圍。按鈕文字不要拆字，窄畫面可改上下排列。
- 數量框下的說明、狀態與左右操作文字邊界需對齊，不以按鈕內距造成額外縮排。
- 確認視窗使用可見標題、清楚的變更前後數量、取消與確認。高度超出螢幕時視窗內可捲動，內容不能被切掉。
- 儲存／送出過程要防止重複操作與內容不一致；失敗要顯示可理解的錯誤並恢復合法操作。

## 交付前檢查

至少實測1440px桌面、768px平板及390px手機，也檢查125%文字放大；涉及確認視窗時再檢查320px窄畫面。核對無橫向溢出、文字未被裁切、checkbox與多行文字對齊、按鈕可操作。PR附實際截圖與測試結果，由A整合核對一致性。

## 取得這次樣式

本次修正推送在 `fix/a-c-order-validation`。推送分支不會自動更新組員；A審核合併到main後，組員保留自己的工作，再於自己的模組分支依agent.md同步：

```powershell
git fetch origin
git merge origin/main
```

每行成功才繼續；有衝突時保留雙方意圖並處理，不直接覆蓋共用CSS。重啟本機Flask並按Ctrl+F5載入新樣式。不要求尚未完成的B／D為等待此修正停下模組製作。
